# 10 · 记忆器实现与细节逻辑

> 本文汇总记忆器从定位、架构、接口、读写链路到数据契约、设计不变量、边界代价与验收标准的完整实现逻辑，可直接作为开发文档 4.6 节实体（或拆为 4.6.0 总纲 + 4.6.x 分节）。

---

## 一、定位与职责边界

记忆器的定位是一句话：**把"状态连续性"从 Agent 的内部能力中剥离，升级为独立的运行时控制平面。**

长期任务的连续性不能依赖对话历史无限增长。上下文窗口只是"一次调用期间的临时注意力空间"，它天然承担不了四件事：状态保存、跨阶段连续、证据追溯、错误恢复。把记忆留在窗口里，等于拿寄存器当硬盘用；把记忆做成 Agent 的一个属性（conversation buffer + 向量库），则必然缺四样东西——**无版本、无来源、无失效、无准入**。这四样缺失让有损转写变得不可检、不可回、不可纠，错误结论被引用、被摘要、再被引用，逐步获得"事实地位"。记忆坍缩的本质不是记忆变少了，而是**记忆变脏了，并且失去了质疑自己的能力**。

因此记忆器只做一件事——状态连续；同时明确四个"不做"：

| 部件 | 负责 | 明确不负责 |
|---|---|---|
| 通信器 | 信息流动（标准化、字段投影、投递） | 状态沉淀 |
| **记忆器** | **状态连续（召回、装配、写回、巩固）** | 判断结论对错 |
| 审计器 | 可信准入（结构/证据/风险/质量 → `PolicyDecision`） | 替代业务推理 |
| 恢复器 | 现场重建（Checkpoint + Capsule + Evidence） | 重新规划任务 |
| 调度器 | 预算超限后的降级决策 | 改写已封口的 `ContextPack` |

这个定位推出一条贯穿全设计的硬约束：**Agent 与存储之间不存在直连通路。** Agent 不能检索、不能写库、不能指定上下文内容；只能提交工况、消费封包、回交结果。召回决策权与写入决策权全程在记忆器。

与之配套的一句设计口诀：**请求是一张报到单，不是一张搜索单。** Agent 描述"我是谁、在哪一步、办什么事、有多大空间"，绝不描述"我要哪些记忆"。

## 二、设计前提：三层根因

方案的每个机制都必须能对回一条根因，否则就是堆部件。

**第一层 · 物理约束（不可改）。** 自注意力 O(n²)，KV cache 随长度线性增长，窗口不可能无限。更关键的是长窗口 ≠ 长记忆：标称 128K 的模型在 64K 之后召回率明显下降，**有效长度通常只有标称的 1/2~1/4**。"不依赖长窗口无损外推"是训练分布问题，不是工程调优问题。

**第二层 · 模型行为（不可改）。** 注意力稀释让概率质量摊薄到所有 token，加上训练分布导致答案偏向首尾，形成 Lost in the Middle 的 U 型曲线——于是**信息"在场" ≠ 信息"可用"**，丢失有两种：没放进去，和放进去了取不出来。复述即有损：每轮用自己的话重述目标，最先被滤掉的是高通细节（数值、边界条件、否定条件）。摘要天然偏向"发生了什么"，丢掉"禁止做什么""尚未确认什么"，而长任务里未决问题与禁令往往比已确认事实更决定成败。

**第三层 · 工程放大（唯一可改）。** 前两层是属性，改不了；可改的是把记忆从 Agent 的属性提升为系统控制平面，补齐版本、来源、失效、准入。

据此，机制与根因一一对应：

| 根因 | 对应机制 |
|---|---|
| 窗口是工作内存不是存储 | 记忆外置为控制平面；上下文按需装配，占用与任务长度解耦 |
| 注意力稀释（在场≠可用） | 硬门控 + 分类型配额 + 分区预算；只给当前节点最小充分集；硬约束进 L0 不可压缩区并置于头部 |
| 压缩有损 | 先引用化、后摘要；分层压缩（确定性 → 模型）；摘要带 `source_refs`/`content_hash`，不替代证据 |
| 结论固化、无来源 | Evidence + Provenance + `authority_level`；晋升需审计准入；`supersedes` 链保留版本 |
| 语义漂移 | 目标与约束作为 Mission State 不可变字段，下游只能引用不能改写 |
| 否定信息消亡 | `openQuestions` / `blockers` / HARD 约束作为一等公民字段，永不压缩 |
| 无失效、无治理 | 生命周期状态机 + 遗忘策略 + 冲突标记 |

值得注意的是：这张表只有第一行是"记忆架构"，其余全是"治理"。这正是与 AutoGPT（有向量库但没有治理结构，故超限即截断、新旧矛盾并存、模型自述与工具结果同权）和 MemGPT（解决了"装得下"，没解决"信得过"，且把换页决策权交给模型自身）拉开差距的地方。

## 三、总体架构：五层与控制权归属

自顶向下五层，上层只能调用下层接口，不得反向依赖；所有策略随 `policy_version` 固定，保证同一请求可复现。

**S1 接入与契约层。** 只暴露 `recall() / assemble() / commit()` 三个方法——**分离必须落在接口上**，否则"检索、压缩、预算、装配四者分离"只是文字。`schema_version` 直接复用通信器的 Schema Version / Adapter 机制，系统内不出现两套版本语义。请求缺字段、越权、版本落后一律返回结构化拒绝码，不给空结果。

**S2 策略与决策层（控制权落点）。** `ContractResolver` 把 `node_contract` 翻译成工序标配清单与分类型配额；`ScopeGuard` 先做租户/权限/时效/状态四维定域；`BudgetPlanner` 切 L0~L3 分区；`DegradationController` 校验降级单调性。策略版本随请求固定，同请求重放应得同一结果。

**S3 召回与装配层。** `RecallOrchestrator` 并行调度四路（点名直取、FTS5 词项、ANN 向量、图关联），**硬门控结果先定域，ANN 只在合法域内执行**；红线与点名直取不进入评分、不占配额、优先入 L0。`FusionRanker` 做 RRF 融合与分档归一，矛盾对标记阻塞而非择一。`Compressor` 先引用化、后摘要，摘要须通过数字/实体/日期比对。产出后封口，`content_hash` 锁定。

**S4 写入与治理层。** `AdmissionGate` 区分工具证据与模型自述，后者默认 `CANDIDATE`；`PromotionFSM` 管 `CANDIDATE → PENDING_REVIEW → ACTIVE / REJECTED / NEED_EVIDENCE`，PENDING 默认不参与在线召回；`WriteCoordinator` 用一次事务提交工作状态 revision、情节事件、证据引用与审计事件，大对象走两阶段预提交 + 孤儿回收。新版本追加并置 `supersedes`，不覆盖旧记录。

**S5 存储与索引层。** SQLite(WAL) 为权威记录唯一真相源；FTS5 external content 表、向量索引、关系邻接表都是**可重建的派生视图**；Evidence / Artifact 内容寻址，库内只存 hash 与 uri。

部件分工与不负责项：

| 部件 | 负责 | 明确不负责 |
|---|---|---|
| `MemoryService` | 三方法唯一入口、版本兼容 | 业务推理、决定给什么 |
| `RequestGate` | 校验身份·工序·容量，结构化拒绝 | 召回策略 |
| `ContractResolver` / `ScopeGuard` | 工序→类型配额；硬门控定域 | 相似度评分 |
| `RecallOrchestrator` | 四路并行调度、候选并集 | 决定预算与准入 |
| `DirectRefResolver` | 点名直取，免评分、优先入 L0 | 语义扩展 |
| Lexical / Vector / Graph Retriever | 词项 / ANN / 关系三路召回 | 判断结论可信 |
| `FusionRanker` | RRF 融合、分档归一、冲突标记 | 在矛盾事实中择一裁决 |
| `PackAssembler` + `Compressor` | 分区预算、降级、先引用后摘要、校验 | 静默丢弃 L0 |
| `AdmissionGate` + `PromotionFSM` | 写入资格与晋升状态机 | 判断结论对错（归审计器） |
| `WriteCoordinator` | 一次事务、幂等、追加不覆盖、回执 | 重新规划任务 |
| `MemoryStore` | 权威记录 + 可重建派生索引 | 可信准入 |

## 四、接口契约

### 4.1 三个方法

`recall(request) -> CandidateSet`、`assemble(candidates, request) -> ContextPack`、`commit(batch) -> CommitReceipt`。读与写事务语义完全不同，必须分开；对内 recall 与 assemble 也必须分离，否则"召回到了但被裁掉"这类故障无法归因。

### 4.2 请求字段：四组

**① 身份与定位（全 P0）**：`request_id`（幂等+追踪）、`tenant_id` / `user_id`（硬门控第一维）、`task_id` / `run_id`（归属与重跑隔离）、`step_id`、`agent_id` / `node_id`（ACL 与配额）、`capability_id`（能力级权限边界）、`trace_id`、`graph_version`、`context_revision`（乐观锁，落后即拒）、`schema_version`。

**② 任务意图（P0）**：`node_contract`（当前节点的 `inputs` / `outputs` / `required_memory_types` / `forbidden_capabilities`，决定召回类型与配额）、`objective_ref`（指向 Mission State 的不可变引用，**不是目标文本**）、`step_intent`（短文本）、`scope`（subject / project / `classification_max`）、`desired_memory_types`（由契约派生，Agent 可声明但不得越权扩大）。

`objective_ref` 是"复述即有损"在接口层的解：目标在系统内只有一个原件，任何下游节点拿到的都是同一版本锁住的对象，没有转写机会。

**③ 显式引用线索（P1）**：`explicit_refs[]`（上一步产出的 `evidence_refs` / `capsule_refs`，确定性命中、不占配额、不参与相似度、优先入 L0）、`focus_entities[]`（实体名，用于有限跳数扩展，**不是自然语言 query**）、`relation_hops`（建议 ≤2）、`exclude_refs[]`（主动排除已知冲突或已失效版本）。

**④ 约束与预算（P0）**：`token_budget`、`memory_policy`（`{policy_version, allow_pending, promotion_gate, ttl_override, require_evidence_for_facts}`）、`degradation_attempt`（单调性校验输入）、`deadline_ms`、`response_format_allowed`（`FULL/EXTRACT/SUMMARY/REFERENCE` 允许集，约束压缩上限）。

### 4.3 请求里不该出现的东西

历史对话原文或旧 prompt、目标文本复述、`top_k` / 相似度阈值 / query 向量、Agent 自判的"事实"（属 `commit` 且须过审计）、打分权重（属 `memory_policy`）、无上限的 `desired_memory_types`。检验口诀：**请求体里 Agent 写的字越少，接口越对**。

### 4.4 拒绝码（必须能拒绝，且给结构化原因）

| 码 | 触发 | 处理 |
|---|---|---|
| `INVALID_SCOPE` | 缺 tenant / 跨租户 | 硬拒绝 + 审计 |
| `STALE_CONTEXT_REVISION` | revision 落后 | 拒绝，要求重取工作状态 |
| `GRAPH_VERSION_MISMATCH` / `SCHEMA_INCOMPATIBLE` | 版本不符 | 报错，禁止静默误读 |
| `CAPABILITY_DENIED` | 能力越权 | 硬拒绝 |
| `BUDGET_BELOW_L0` | 预算装不下 L0 | 抛 `CONTEXT_BUDGET_EXCEEDED`，交调度器降级，绝不静默丢弃约束 |
| `DEGRADATION_NOT_MONOTONIC` | attempt 增加但 token 未下降 | 判不可降级 → 转人工，防死循环 |
| `CONTRACT_UNCOVERED` | 工序无对应契约 | 显式告警，不许静默返回空包 |

## 五、读链：七步细节

**第 1 步 · 硬门控前置定域（先锁门，再找东西）。** 关掉四片区域：跨租户/跨项目、权限不足、时效过期、未准入（PENDING）。顺序不可颠倒——若"先召回再过滤"，越权内容已经进过候选集，口子就开了。落地机制建议 **按 `tenant_id` 分片索引为主 + 过采样后过滤兜底**：权限定域直接落在分片上，租户内再按 `classification` 二级过滤，避免大租户下 pre-filter 退化为近暴力。

**第 2 步 · 四路并行召回。** 点名直取（按 ID 精确取，免评分）、FTS5 词项、ANN 向量、图关联（邻接表 + `WITH RECURSIVE`，跳数硬上限）。ANN 只负责其中一路，且必须在定域之后执行。

此处必须如实标注一个实现事实：默认嵌入适配器为**确定性回退实现**（hash/词频投影类），与 BM25 高度相关，两路 RRF 不但无互补增益，还会稀释头部精度。文档应命名为 `DeterministicFallbackEmbedding`（可插拔接口 + 内置回退），指标分三行报：BM25-only Recall@K / Hybrid Recall@K / Δ融合增益；Δ≈0 就如实写"内置回退不提供语义泛化，语义增益依赖注入的外部嵌入"。RRF 常数 k 应随适配器切换：确定性回退取 20~40（强化名次差），真实嵌入取 60~100（两路互补时更稳），k 做成 `memory_policy` 项。

**第 3 步 · 分类型配额。** 全局截断 100 应改为分类型配额：Working 全量、Episodic 40、Semantic 30、Procedural 10、**Profile/Constraint 全量且不占配额**、Evidence 按引用直取不占配额。理由：Profile 与直接 ID 引用属确定性命中，不该参与相似度竞争——"关键约束应优先于相似度进入上下文"必须在配额层落实，只在排序层加权不够。

**第 4 步 · 融合与评分。** 八个维度（Rel / Fresh / Utility / TokenCost / Conflict / Authority / Scope-fit / Coverage）直接线性加权会出四个问题，逐条处理：

- **量纲不一致**：先分档归一（0/0.25/0.5/0.75/1 或 log 压缩）再加权，否则时间衰减项会淹没相关性。
- **Utility 冷启动**：新记忆 Utility=0 会被永久压制，需 Beta(α,β) 先验平滑（初值取同类均值）+ 每批留 10~15% 探索配额给低 Utility 高 Rel 的候选。
- **Conflict 分两类**：涉及 HARD 约束或人工决议的冲突**不惩罚、直接上报阻塞**（触发补证 Step 或人工复核）；一般事实冲突才惩罚。否则模型会在两条矛盾事实里"挑一条更像的"，这正是幻觉温床。原则：**宁可停下，不许猜。**
- **TokenCost 移出打分**：放到装配阶段做 `value/token` 贪心背包。留在检索阶段扣分，长证据将永远召不回来。

**第 5 步 · 分区装配。** L0 硬约束与红线（FULL、不可压缩、置于头部以避开 U 型谷底）→ L1 本步必需事实与任务状态 → L2 支撑性背景 → L3 可选扩展。严格自上而下；**L0 任一内容超限直接抛 `CONTEXT_BUDGET_EXCEEDED`，绝不静默丢弃**。

**第 6 步 · 分层压缩。** 先引用化（无损），实在放不下才摘要（有损）。摘要产出后做**数字/实体/日期抽取比对**，与原文冲突即丢弃摘要回退结构化原文——成本极低，比"重试几次"有效得多。Capsule 生成按层区分：Step Capsule 纯确定性字段直取（goal / outputs / evidence_refs / status / errors）；Phase Capsule 用确定性骨架 + 模型**只填非事实性字段**（`summary` / `openQuestions` / `nextStepHints`），而 `confirmedFacts`、`decisions`、`constraints`、`evidence_refs`、`sideEffects` 必须由系统确定性聚合。这样"到底用没用模型"不再是含糊问题。

**第 7 步 · 封口与归因。** 生成 `ContextPack`（`pack_id` / `content_hash` / `sections[{zone, level, source_refs, representation, tokens}]` / `omitted[]` / `request_snapshot` / `assembly_trace_ref` / `policy_version` / `schema_version`）并锁定不可变。**`CandidateSet` 必须返回 `rejected[{memory_ref, reason}]`** —— 这是"没召回到 / 召回到但未选中 / 压缩时丢失"三种故障的唯一归因依据。归因不了的指标是装饰品。

**时序硬约束三条**：单 Step 一次主请求，补充追取只能走 `explicit_refs` 窄请求且不得改写已有 pack 的 `content_hash`；`ContextPack` 生成后不可变，记忆集未变时同请求重放返回同一 pack；`recall` 与 `assemble` 内部必须分离。读请求的唯一副作用是异步更新 `access_stats`，且明确**不得据此提升 `authority`**。

## 六、写链：两阶段提交

先立硬规矩：**审计器是纯判定部件，只读、无写权限，只输出 `PolicyDecision`；真正落盘的唯一写入方是记忆器。** 否则出现两个写入方，单一真相源与事务边界同时崩。

时序困境不能简单二选一：纯"先审后写"会让 Agent 阻塞在审计上，长任务变串行；纯"先写后审"则内容已进权威表，污染口子实质上开过一次。解法是**同步暂存 + 异步晋升**。

**阶段 1（同步，毫秒级）：先暂存，不等审计。** 记忆器收到 `MemoryWriteBatch` 后做三件事——分类（工具真返回的证据 / 模型自述的结论分开，后者默认 `CANDIDATE`）、建立 staging 暂存记录（不进权威表）、大对象内容寻址上传（blob 先落地，库里只存 hash）。然后**立即**返回 `CommitReceipt(provisional=true, ref)`，Agent 拿临时编号即可继续，完全不阻塞。

**阶段 2（异步）：送审 → 晋升事务。** 把 staging 对象打包成**只读快照**送审计器（只读快照、不回调在线召回，避免记忆器↔审计器循环依赖）。拿到 `PolicyDecision(ALLOW)` 后，记忆器执行一次事务：权威表 `INSERT(status=ACTIVE)` → 派生索引更新 → staging 标记 `PROMOTED`（**不删，留审计痕迹**）→ 审计事件写入 → 工作状态 `revision+1`。任一强一致写入失败整批回滚，staging 原样保留可重试。

`REJECT` 或 `NEED_EVIDENCE` 时：staging 标对应状态并留痕，**撤销临时 ref**、通知调度器触发补证 Step。绝不能让 Agent 拿着被拒内容继续往下跑——这是最容易漏的一步。

**四个必须处理的细节**：

| 细节 | 风险 | 做法 |
|---|---|---|
| 引用一致性 | ① 的 ref 指向 staging，⑥ 后对象换身份，下一步拿旧 ref 找不到 | ref 用**逻辑 ID + 别名映射表**，晋升只改映射、不改 ref |
| TOCTOU 重校验 | 审计看快照，晋升时库可能已被别的步骤改动 | 晋升事务内带 `context_revision` 乐观锁 + 重跑冲突检测，失败退回 `CANDIDATE` 重审，**不能"审过就无条件放行"** |
| 幂等 | Agent 重试会重复建 staging | 键 `(task_id, run_id, step_id, attempt, batch_seq)`；同键返回上次 receipt，新 attempt 才允许新批次并 `supersedes` 旧版 |
| 大对象两阶段 | blob 混进事务拖垮写入 | 阶段 1 先内容寻址落地，晋升事务只引用 hash；pending 超 TTL（建议 1h）标 `orphan` → GC 清理并留痕 |

**状态机**：`CANDIDATE`（staging，不参与召回）→ `PENDING_REVIEW`（staging，不参与召回）→ `ACTIVE`（权威表，参与召回）／`REJECTED`（留痕，撤销引用）／`NEED_EVIDENCE`（触发补证）；对象层另有 `ORPHAN`。PENDING 一律不进在线召回，除非 `memory_policy` 显式 `allow_pending=true`；超时未裁决**保持 CANDIDATE，绝不默认放行**。

**闭环**：回执编号返回后，下一步填进 `explicit_refs` 点名直取，回到读链。

## 七、数据契约与存储

只立三份契约，其余全部引用它们，六类记忆字段表各自为政的问题会一次性消失。

**1. `MemoryRecord`（存储信封，六类共用）**：`memory_id, memory_type, tenant_id, user_id, task_id, run_id, step_id, trace_id, scope, classification, status, validity_window{valid_from, valid_to}, content_hash, version, supersedes[], source_refs[], evidence_refs[], authority_level, promotion{reason, actor, policy_version, at}, access_stats{last_access, access_count}, token_estimate, created_at, updated_at`；payload 按 `memory_type` 分字段，信封统一。

**2. `MemoryWriteBatch`**：`batch_id, idempotency_key, working_state_delta, episode_candidates[], evidence_refs[], artifact_refs[], audit_feedback[], promotion_requests[], errors[], transaction_mode: STRICT|BEST_EFFORT`。

**3. 在线三件套**：`MemoryContextRequest` / `MemoryCandidateSet`（含 `rejected[]`）/ `ContextPack`（含 `omitted[]` 与 `assembly_trace_ref`），字段见第四、五节。

存储按数据性质分层，而非全塞一张表：

| 数据 | 存储 | 理由 |
|---|---|---|
| 记忆权威记录（六类） | SQLite（WAL，`busy_timeout` ≥ 5s） | 强一致、事务、可随 checkpoint 快照 |
| 关键词倒排 | FTS5 **external content 表** | 免双写，触发器同步，权威表单一真相源 |
| 向量索引 | 进程内派生 / 可注入 ANN | 允许丢失，可重建 |
| 关系图 | 邻接表 + `WITH RECURSIVE` | 有限跳数扩展，跳数硬上限 |
| 大对象（Evidence / Artifact） | 内容寻址对象存储，库内只存 hash/uri | 两阶段协议的物理基础 |

架构约束：**所有索引都是权威表的物化视图**。提供 `memory_index_rebuild()` 运维接口 + 启动时 `index_version` 校验（版本不符即重建）。写事务要短，大对象不进事务；多 Step 并发写回的 `SQLITE_BUSY` 是必然出现的。

多机一致性必须明确边界：当前为单进程 SQLite，本质不支持多机。建议按 `task_id` 分片 + 复用已有 Resource Lease 租约机制决定归属节点，与调度章节互相印证；跨分片写回（如共享 Evidence）**没有原子性**，文档里"一次事务"必须注明作用域为单进程单分片。

## 八、设计不变量（实现时逐条断言）

1. Agent 不具备检索决策权：请求体中不得出现 query、top_k、相似度阈值、历史对话文本、目标文本复述。
2. 硬门控先于一切召回；越权召回数恒为 0。
3. L0 不可压缩；预算装不下 L0 直接抛 `CONTEXT_BUDGET_EXCEEDED`，绝不静默丢弃。
4. 未准入内容不进在线召回（`allow_pending` 默认 false）。
5. 冲突不择一，标记后阻塞补证。
6. 追加不覆盖，旧版本可回溯（`supersedes` 链）。
7. 所有索引是权威表的物化视图，可重建。
8. 降级单调：每次降级 `estimated_tokens` 严格下降，否则转人工。
9. 每次装配可归因：未入袋内容必须区分"未召回 / 召回未选中 / 压缩丢失"。
10. 审计器无写权限；记忆器是唯一落盘方。
11. 同一请求重放应得同一 `content_hash`。

## 九、边界、代价与局限性

**这一节不是自我批评，是必须主动声明的设计边界。** 七条按"会不会打脸题设目标"排序。

**1. L0 单调膨胀 → 预算悖论（最致命）。** 硬约束、禁令、未决问题只增不减，且规定不许压缩、不许丢、不参与竞争；而 `token_budget` 固定，两条线迟早相交。撞墙后"每次降级 token 必须严格下降"在数学上无法成立，系统只能判"不可降级 → 转人工"——即超长程等于迟早要人接管。**缓解而非根除**：约束必须有生命周期（作用域、失效条件、被 `supersedes` 后退出 L0），区分"全局永久红线"与"阶段局部红线"，全局项设硬上限。

**2. 契约覆盖瓶颈。** 配置靠人预先写好的 `node_contract`，遇到未预料的工序或新任务类型就配不出东西；而 Agent 已被剥夺"自己开口要"的权利，失败模式从"偶尔漏一条"变成"整类缺失"。缓解：保留受控的窄补充通道（`explicit_refs`）、契约可版本化在线扩展、**契约未覆盖时显式告警而非返回空袋**（`CONTRACT_UNCOVERED`）。

**3. 治理者也需要判断力 → 循环依赖。** 纯规则覆盖不全；改用模型判断"这步配什么"，等于把上下文选择权交给另一个模型，绕回原问题。审计器判断"结论对不对"同样需要上下文，形成记忆器 ↔ 审计器依赖环——异步晋升只解了时序，未解依赖。缓解：明确划出"系统内唯一允许用模型做检索判断的环节"并受同等证据约束；审计器只读快照，不回调在线召回。

**4. 成本没解耦，只是搬家。** 上下文大小与步数解耦，但存储、候选扫描、旧版本过滤的成本仍随步数增长。O(n) 从 prompt 挪进了数据库。缓解：版本链定期固化归档、旧版本按 `status` 在权威表直接过滤（不进候选集）、设保留期。

**5. 回执闭环 → 自我强化的信息茧房。** 下一步凭上一步回执直取，链路越来越依赖系统刚存的东西，外部证据被挤出；加上 Utility 按"历史是否改善成功率"反馈更新，形成被选中→分数升高→更易被选中的正反馈。探索-利用问题，靠"唤醒次数不提升 authority"挡不住——Utility 本身就是反馈量。缓解：强制探索配额、`access_count` 与 `authority` 在代码层彻底分离、定期强制注入外部证据。

**6. 三道闸门的失效模式。** PENDING 不参与召回 → 正确但未审完的信息审核期完全不可见，Agent 可能基于旧版本决策（一致性与可用性无最优解）。冲突一律阻塞补证 → 补证本身又要召回，召回又看见矛盾，形成活锁，必须设终止条件（超时 / 降权择一 / 人工兜底）。一次事务整批回滚 → 强一致只在单进程单分片内成立。

**7. 验证盲区。** 金丝雀探针按已知事实埋设，能测"能否取回已知那条"，测不出"设计者根本没想到的那条约束没被配进来"——而第 2 条恰好属于后者。Recall@T 跑满也不证明架构没问题。

**元结论：治理强度与自治程度成反比。** 每加一道闸门都是把决策从 Agent 挪给规则或人，任务越长撞上闸门的概率越接近 1。这不是实现缺陷，是用"信得过"换走了一部分"跑得远"。

因此目标口径必须写成「**风险分档下的分级自治 + 人工兜底**」，并在验收中加反向指标 **转人工率**。可直接进文档的边界声明：

> 本设计以可信性优先，通过显式闸门换取状态连续性与可审计性，其代价是自治程度随治理强度上升而下降。系统适用于风险分档明确、允许人工兜底的中长程任务；对于要求无限长度且全程无人介入的场景，不可压缩区累计与固定预算的矛盾不可通过参数调优消除，须引入约束生命周期与分级自治策略。

## 十、验收标准与实验设计

**测试方法先行**：用金丝雀探针（动态版 NIAH）——在第 1/10/30 步埋入 20~50 条金丝雀（项目代号、预算上限、禁用供应商、未决问题），在第 10/30/60/100/200 步探测，画 Recall vs 步数曲线；期望本方案平坦，基线衰减。

**三个 baseline 必设**：B1 长窗口全量拼接（实测"无损外推"到底行不行）、B2 滑动窗口/截断（AutoGPT 式）、B3 top-k 向量 RAG（MemGPT 式，解决装得下但没解决信得过）。

| 维度 | 指标 | 目标 |
|---|---|---|
| 不丢失 | Critical Info Recall@T | ≥95%，**硬约束类 100%** |
| 不漂移 | 数值/日期/实体保真率 | ≥99% |
| 不漂移 | 目标关键字段重合率 | ≥0.98 |
| 不污染 | 幻觉沉淀数 | **=0（硬断言）** |
| 不污染 | 冲突检出率 | ≥90% |
| 可回溯 | Provenance 覆盖率 | ≥95%，关键结论 100% |
| 不越权 | 越权召回数 | **=0（硬断言）** |
| 解耦 | 上下文-步数斜率 | ≈0，P95 ≤ 预算 |
| 效率 | 检索时延 P95 | <200ms 本地 / <500ms ANN |
| 恢复 | 检查点恢复时间 | <30s |
| 压缩 | 10:1 时 Recall 降幅 | ≤5% |
| 可复现 | 同请求重放 `content_hash` 一致率 | 100% |
| 归因 | 人为制造"召回未选中"100 例，`rejected[]` 覆盖率 | 100% |
| **诚实指标** | **转人工率（按步数画曲线）** | **如实上报** |

**图与结论一一对应**（一张图只证明一个可证伪结论）：F1 折线+置信带（召回随步数）、F2 折线+预算水平虚线（占用解耦）、F3 分组柱（硬约束缺失，本方案恒 0）、F4 100% 堆叠柱（失败归因三段构成）、F5 水平条形（消融 ΔRecall）、F6 折线（压缩比 vs 保真）、F7 混淆矩阵热力图（越权，非对角恒 0）、F8 阶梯折线（转人工率）；辅助可用时延 CDF 曲线。

其中 F4 最有价值：B2 的失败多来自"压根没召回到"，B1 的失败多来自"召回到但没被选中"——两种失败机制不同，正好印证"在场 ≠ 可用"。

**所有指标数值必须以实测为准**，固定随机种子、多次重复、报 95% CI 与配对 Wilcoxon 检验 p 值、保留原始日志；步数跑不到 200 就截到 100，不要编造"过于顺滑"的曲线。
