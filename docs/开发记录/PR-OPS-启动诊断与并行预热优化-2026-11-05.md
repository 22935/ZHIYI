## 修改与边界

1. Java 和 Vite 在 PostgreSQL/Redis 就绪后提前拉起，使 Vite 的准备工作与 Schema、授权投影、AI 初始化重叠。
   这是子进程间的并行；状态记录仍由原启动器顺序保存，没有新增线程或第二个状态管理器。
2. 保留 AI → Java → Frontend proxy 的正式就绪检查；Electron 只在这些门禁成功后拉起。
   提前启动的 Vite 进入原有进程记录，失败清理继续复用 `down()`。
3. 通过 stderr 实时输出每个启动阶段及耗时，stdout 继续保留原 JSON 合同。
   每个完整启动 session 新增 `startup-timings.json`，失败阶段也会记录。
4. 启动器使用 Python `-u`，显示总耗时；新增 `-NoPause` 供自动化返回实际退出码。
   默认失败窗口明确显示“Startup has failed”，避免把等待关闭误认为仍在启动。
5. 修复 `status()` 的诊断串扰：PostgreSQL、Redis、Java 独立检查，一个失败不再把其他健康服务标为失败。
   已退出服务不再尝试连接；PostgreSQL 就绪查询增加进程超时和连接超时。
6. 部分存活的环境仍明确拒绝自动重启，但错误会列出不可用服务，例如 `unavailable: java`。
7. `test_desktop_open.py` 将旧的 `port_free` Mock 修正为实际调用的 `release_port`，避免单测探测真实端口。

不修改现有数据、凭据、数据库结构、Runtime 执行合同或模型配置。
Vite 提前启动可能受 CPU/磁盘竞争影响，节省幅度必须以实际启动测量为准，不能把约 39 秒的串行区间全部当作已获得的收益。
