# ACG 初始规划控制策略兼容修复

## 现场证据

用户测试的 Mission 为 `mission_8f979e0f50b1`，Run 为 `run_b47dbc9938f4`。本机 AI 日志记录 `_materialize_acg_run → accept_initial` 后抛出 `Planning Commit rejected: CONTROL_BARRIER_BLOCKED`。只读查询确认该 Run 已失败，`reviewMode=auto`，保留 `planningDeferred=true`、`planningCommitRequired=true`，尚未生成步骤或 ACG，没有该 Mission 的 Planning Commit 记录。

被拒绝的模型候选没有持久化，无法逐字还原现场输出。当前初始提交的其他控制拦截条件与空 Run 状态不符；用含 `verification_loop` 的合法 TaskPlan 可以复现“规划器产出候选、随后提交边界拒绝”的不兼容路径。该错误不是业务预算校验失败，也不证明发生了文件写入。

## 原因

现有初始 Planning Commit、初始图物化均明确只支持无控制节点的 DAG。TaskDecomposer 原先允许生成验证循环，完整能力分阶段规划的关系提示还会主动建议 `verification_loop`。因此“生成、检查、修正后重验”一类正常目标可能触发尚未支持的初始控制图。

## 修改

- 初始规划 `initial_commit_candidate` 的模型输入加入 DAG-only 合同，Schema 限定 `controlPolicies` 最多零项。任务拆解提示版本更新为 v8。
- 要求保留原任务的验收、修正和复核义务，使用有明确边界的前向任务序列，未解决事项必须报告；不删除模型输出中的控制策略来伪造成功。
- 单次生成路径中，模型忽略约束时沿用一次完整候选修复；分阶段路径只重试关系单元，不重生成或替换已冻结任务。
- 修复后仍提出循环时，明确返回 `INITIAL_CONTROL_GRAPH_UNSUPPORTED`，不再将它误报为源版本陈旧。
- Runtime 展示 Planning Commit 拒绝时保留 `reason`，避免不同拦截原因都只剩同一个代码。
- 初始物化和提交控制检查保持原样；既有非初始规划的控制循环能力保留。

涉及 `components/planner/task_decomposer.py`、`runtime/planning_commit.py`、`runtime/workflow_runtime.py` 及定向回归测试。未改动已失败 Run 的状态、数据库内容或交付物。
