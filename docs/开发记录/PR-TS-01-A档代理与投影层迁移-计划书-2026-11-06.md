# A 档（代理与投影层）TS 轻量化迁移计划书

> **文档定位**：本文件是待评审的实施方案，用于把 Java 后端中"纯代理 + API 投影"的部分迁到 TypeScript。
> 评审通过后再进入实施；实施期间本文件随进度更新"状态"字段。
>
> **状态**：待评审
> **范围**：仅 A 档（代理与投影层）。**不含**认证/会话、对话持久化、SSE 落库、数据迁移（这些属 B 档）。
> **前置结论**：本地单机产品形态已确定；Java 的职责被拆为 A / B / C 三档，本文只覆盖 A 档。

## 1. 背景与判断依据

Java 后端现状：**299 文件 / 14,917 行 / 25 个 controller / 140 个端点 / 5 张表**。

| 指标 | 数值 | 说明 |
|---|---:|---|
| 端点 | 140 | 其中 A 档 **108** 个 |
| 数据表 | 5 | `User` / `Role` / `Conversation` / `Message` / `LoginSession`（全部属 B 档） |
| `projection` 包 | 5,368 行 / 148 文件 | 上游 DTO 的投影与映射，A 档占 5,048 行 / 135 文件 |
| 启动耗时 | 16.2s | `Started KinlinAiApplication in 16.207 seconds` |

**核心判断**：A 档是"把 Python 的 JSON 转成另一份 JSON"，几乎不含本地状态；把它迁到 TS 后，`Controller + DTO + Mapper` 三份样板可以塌缩成 `zod schema + 内联 mapper`，预计 9.7k 行 → 2k 行左右。

## 2. 目标与非目标

### 2.1 目标

1. A 档 **108 个端点**全部由 TS `local-api` 提供，响应形状与 Java 版本逐字节对齐（允许的差异见 §6.4）。
2. 前端**零改动**：沿用 `http://127.0.0.1:18080` 的 `/api`、`/ai` 前缀与路由。
3. 迁移期可随时回滚：TS 作为门面，未迁移路由回落到 Java（18081），一条环境变量切回全量 Java。
4. 用契约快照（golden）锁住 108 个端点的响应，作为迁移验收与后续回归的唯一依据。
5. 迁移完成后，A 档相关 Java 代码（约 9.7k 行 / 180 文件）可整体删除。

### 2.2 非目标（本期明确不做）

| 项 | 归属 | 原因 |
|---|---|---|
| `AuthController` / `LoginSessionService` / 安全过滤器 | B 档 | 涉及信任边界与令牌语义，需单独设计 |
| `ChatService` / `ConversationService` / `ChatController` | B 档 | 涉及短事务与对话归属校验 |
| `ChatStreamPersistenceService` / `AgentConversationPersistenceService` | B 档 | 流式事件幂等落库，规则密集、测试密集 |
| PostgreSQL → SQLite 数据迁移 | B 档 | A 档不读写数据库，无数据依赖 |
| 删除 Java 进程本身 | B 档完成后 | 本期只做"路由与实现"，进程形态不变 |
| 前端 UI/路由/状态管理改造 | 不涉及 | 契约不变，无需改前端 |
| Python agent 任何改动 | 不涉及 | A 档只做透传与投影 |

## 4. 目标架构

### 4.1 运行时拓扑（迁移期）

```text
Electron / 前端
   │  /api, /ai  (127.0.0.1:18080)
   ▼
TS local-api（Fastify，18080）
   ├── 已迁移路由 → 直接处理（透传 / 投影）
   ├── 未迁移路由 → 反向代理到 Java（18081）
   └── /ai/chat/text/stream 等 SSE → 直连 Python 透传
   │
   ├── Python AI / AgentOS（127.0.0.1:18761）
   └── Java 遗留（127.0.0.1:18081，迁移期兜底）
```

切换完成后：`local-api` 占 18080，Java 进程不再启动。

### 4.2 目录结构

```text
apps/local-api/
├── package.json            # tsx dev / tsc build（本地模式直接 tsx 跑源码）
├── tsconfig.json
└── src/
    ├── server.ts           # Fastify 装配、路由注册、兜底代理
    ├── config.ts           # Python/Java 地址、内部 token、超时（对齐 PythonServiceProperties）
    ├── upstream/
    │   ├── python.ts       # 基础 client：鉴权头、Trace-Id、超时、错误分类
    │   ├── agentosPaths.ts # 由 AgentOsPaths.java 平移，路径字面量单点定义
    │   ├── envelope.ts     # AGENTOS_* 错误信封 + `_httpStatus` 标记
    │   └── sse.ts          # SSE 透传：心跳、取消、错误事件
    ├── routes/
    │   ├── agentos.ts      # 77 个端点
    │   ├── capabilities.ts # 21 个能力代理端点
    │   ├── ai.ts           # /ai/** 非流式 + 流式
    │   └── files.ts        # 文件上传/下载
    └── projection/         # zod schema + mapper（按资源分文件）
└── test/
    ├── contracts/          # 108 个端点的 golden 快照
    └── *.spec.ts
```

### 4.3 三条请求链路

| 链路 | 处理方式 | 关键约束 |
|---|---|---|
| 普通 JSON | `fetch` 上游 → 校验 → 投影 → 返回 | 保持 `_httpStatus` 语义与 `AGENTOS_*` 错误码 |
| SSE | `fetch` + `ReadableStream` 透传 | 心跳、客户端断开取消上游、错误事件码不变 |
| 文件 | Electron main 写盘；或 TS 流式转发 | 保留现有大小限制与目录白名单 |

## 5. 迁移策略（绞杀者模式）

### 5.1 路由切换

1. `local-api` 启动即监听 18080；Java 在迁移期以 `--server.port=18081` 启动。
2. `local-api` 维护 `MIGRATED` 路由表；命中则本地处理，未命中则 `proxy → 18081`。
3. 每个阶段结束，用环境变量 `LOCAL_API_MODE=ts|java|all-java` 控制：
   - `ts`：已迁移路由走 TS，其余回落 Java（默认，渐进）；
   - `java`：全量回落 Java（回滚开关，秒级生效）；
   - `all-ts`：迁移完成后使用，Java 不再启动。
4. 前端与 Vite 代理完全不动（仍是 18080）。

### 5.2 阶段划分

| 阶段 | 内容 | 交付 | 验收 | 工期 |
|---|---|---|---|---:|
| P1.1 | 骨架：Fastify、配置、`python.ts` 基础 client、兜底代理、端点清单导出、golden 采集脚本 | 可启动、全量回落 Java、108 端点清单冻结 | 前端行为与现状完全一致；回落日志可观测 | 2 天 |
| P1.2 | AgentOS 命令/查询：missions、runs、artifacts、materials、resources、workspace、events（77 个端点中的 ~50 个） | 路由 + 透传 + 对应投影 | 该组 golden 全绿；错误码与状态码一致 | 4 天 |
| P1.3 | AgentOS 聚合查询：`AgentOsObservationController`（13 端点，引用 11 个投影子包）、`AgentOsReviewController` | 聚合投影实现 | 快照全绿（含空数据、缺字段、上游 4xx/5xx） | 3 天 |
| P1.4 | `/ai/**` 非流式代理 + SSE 透传（含取消、心跳、错误事件） | `ai.ts` + `sse.ts` | 断网/超时/取消三类用例通过；前端流式无回退 | 2 天 |
| P1.5 | 能力代理 21 端点 + 文件 + 健康 | `capabilities.ts`、`files.ts` | 快照全绿；上传大小/类型限制与现状一致 | 3 天 |
| P1.6 | 双跑对账、灰度、Java 下线准备（只删 A 档、保留 B 档模块） | 对账报告 + 回滚演练记录 | 连续 3 天回落命中 0；回滚演练通过 | 2 天 |
| **合计** | | | | **16 个工作日（1 人）** |

### 5.3 双跑对账（P1.6 核心）

- **只读端点（GET）**：影子模式，同一请求同时打 TS 与 Java，规范化易变字段（时间戳、requestId、traceId）后 diff，要求 100% 一致。
- **写端点（POST/DELETE）**：不做影子（有副作用），采用"阶段内人工回归 + goldens 覆盖 + 单侧执行"，并在灰度期观察 Java 回落日志与前端报错率。
- 对账结果产出 `docs/开发记录/PR-TS-01-对账报告.md`。

## 6. 契约与兼容

### 6.1 路由

- 保留 Java 现有映射，包括 `/api` 别名（Vite 代理按 `/api` 前缀直连后端，Java 侧统一兼容，TS 必须复现该别名规则；**具体剥离规则见待确认 Q2**）。
- 路径中的 id 段必须做百分号编码（对齐 `AgentOsPaths.segment`），查询参数按"非空才拼、保持插入顺序"（对齐 `AgentOsPaths.query`）。

### 6.2 响应与错误

- 保持 `_httpStatus` 内部标记：网关把上游状态塞进 map，controller 取出后映射为 HTTP 状态，并从响应体移除该键（见 `apps/backend/src/main/java/com/kinlin/ai/controller/AgentOsControllerSupport.java`）。
- 错误信封保持 `AGENTOS_*` 码制与 `code`/`message`/`requestId` 三字段；上游不可达时保持 `AGENTOS_GATEWAY_DISABLED` / `AGENTOS_UPSTREAM_UNAVAILABLE` 的现有分支（以 Java 实现为准逐条对齐）。
- 投影只允许"减少字段"，不允许新增或改名；字段裁剪须有 golden 快照佐证。

### 6.3 SSE

保留以下四件事，其余按 Node 原生实现：

1. 心跳事件（沿用 Python 侧间隔，Java 侧未改写，TS 只透传）；
2. 客户端断开 → 取消上游请求（对齐 Java `doOnCancel`）；
3. 网关层错误事件码：`SSE_IDLE_TIMEOUT`、`SSE_MAX_DURATION`（当前默认关闭）、`AI_STREAM_INTERRUPTED`、`AUTH_SESSION_INVALIDATED`；
4. 会话复核（`SessionRecheckGate`）本期**保留在 Java 侧**——迁移期 SSE 若整体走 TS，需把该门同步平移，这是 P1.4 的最大不确定项（见 Q4）。

### 6.4 允许的差异（需逐条评审）

| 差异 | 是否接受 | 理由 |
|---|---|---|
| 响应 JSON 的键顺序 | 接受 | 前端按 key 取值 |
| 未声明字段透传（上游新增字段） | 接受 | 比 Java 更宽松，不破坏前端 |
| 数值精度（Java `BigDecimal` → JS `number`） | **待确认** | 金额/比值类字段需逐个确认 |
| 时间格式 | 不接受 | 必须与 Java 序列化一致（ISO-8601 带时区） |

## 8. 风险与回滚

| 风险 | 影响 | 应对 |
|---|---|---|
| 108 端点契约遗漏 | 前端局部 500/字段缺失 | golden 覆盖率作为阶段门禁；未覆盖即不切路由 |
| SSE 会话复核门语义丢失 | 会话失效后仍能收流 | P1.4 前完成 `SessionRecheckGate` 行为清单；必要时 SSE 暂缓迁移、只迁非流式 |
| 二进制/多部分响应 | 下载/上传损坏 | 单独用例覆盖 `Content-Disposition`、分块与大小限制 |
| 双跑对账误报 | 难以判断差异归属 | 规范化规则先行评审；对账报告逐条签字 |
| Java 回退路由的性能损耗 | 迁移期慢一点 | 可接受；P1.6 后消失 |
| 数值精度差异 | 展示/计算偏差 | `big.js`/`decimal.js` 或字符串透传，按字段清单处理 |

**回滚**：`LOCAL_API_MODE=java` → 全部回落 18081，秒级；Java 进程在 P1.6 前始终保留。
