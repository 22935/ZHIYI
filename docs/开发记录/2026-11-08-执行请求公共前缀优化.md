# 执行请求公共前缀优化

## 问题与范围

`run_db6f32ac2f49` 的历史模型调用输入为 105,128 Token，缓存读取为 9,088 Token，按输入加权命中率为 8.64%。15 条调用记录涉及 10 种原始系统提示词前缀；能力策略与 DeepSeek 输出 Schema 先于共同任务材料出现，限制跨步骤的前缀复用。

本次仅优化明确携带当前 Native 提示词版本的 DeepSeek ExecutionRequest。规划、普通文本、自定义系统提示词、其他提供商及无法识别的输入继续使用原路径。历史任务记录不重写。

## 新结构

1. system：公共内核、执行合同、上下文片段解释规则。
2. user：SharedExecutionContext，包含原 Mission 依据和原本已授权提供的任务材料。
3. system：当前角色、能力策略及供应商适配器注入的输出 Schema。
4. user：ExecutionRequest 的剩余输入，包括当前步骤、上游结果、引用、记忆和工具观察，以及本地 sharedContextRef。

`execution_prefix.py` 在模型调用边界编译消息，不加载额外材料，不建立额外上下文存储。SharedExecutionContext 和 ExecutionRequest 合起来可还原原始输入；材料始终是带信任标签的 user 数据。角色策略保持 system 指令，工具授权仍由运行时判定。

`schemaMessageIndex` 是供应商无关调用合同的内部字段，不作为供应商选项发送。DeepSeek Schema 注入第三条消息，不改写前两条公共消息。字段修复继续保留原始消息及原 Schema，再追加修复消息和当前修复合同。

提示词 renderer 版本升为 v4；优化路径的 stablePrefixHash 对应实际外发的前两条消息，不包含正文。普通调用和流式调用使用同一构造器。
