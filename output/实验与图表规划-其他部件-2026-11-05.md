# 其他部件的实验 · 图表 · 呈现方案

> 承接 2026-11-01 / 11-03 的记忆器讨论。记忆器章节的实验口径（BM25-only / Hybrid / Δ）已定，
> 本文覆盖**其余组件**：规划器、执行器、通信器、恢复器、资源调度、治理审计、演化、端到端。
> 面向国赛技术说明书「实验与验证」章 + 答辩演示。

---

## 0. 三条总原则

1. **一个部件只主张一句话。** 主张先写死，再反推实验；不能让实验去"凑"图。
   - 规划器：「静态优选让常见任务少花构图成本，动态补位让长尾任务不掉队。」
   - 执行器：「拓扑宽度能换成墙钟时间，且逼近关键路径下界。」
   - 通信器：「按字段投递把上下文从 O(ΣS) 压到 O(F)，且答案质量不降。」
   - 恢复器：「任意单点故障下，重复工作量与故障位置无关，只与检查点粒度有关。」
2. **每张图都要有一个"对手"。** 没有基线的图在答辩里等于没做实验。基线只能是：全量拼接 / 从头重跑 / 纯动态规划 / 串行执行。
3. **图必须可复现到命令。** 图脚注写 `脚本 + 数据 json + n + commit`，答辩被问"这数怎么来的"时能当场跑。

## 2. 实验卡

### A. 规划器（Planner：意图解析 → 模板匹配 → 认知路由 → ACG 构建）

**实验 A1｜模板匹配阈值扫描（必做，正文）**
- 自变量：相似度阈值 θ ∈ {0.60, 0.65, …, 0.95}
- 因变量：命中率（应命中而被命中）、误命中率（不该命中却命中）、降级到动态构图的比例
- 样本：40~60 条任务描述，人工标注"是否属于既有模板"，标注口径写进附录
- 图：双轴折线，左轴命中率、右轴误命中率，竖虚线标默认 0.85
- 结论句式：「θ=0.85 时命中率 78%、误命中 4%，是误命中 ≤5% 约束下的最优点。」
- 展示：答辩现场把 θ 改成 0.6 重跑一次，命中率飙升、误命中爆掉 —— 一分钟证明这个参数不是拍的。

**实验 A2｜静态 / 动态 / 混合三方对比（正文小图或附表）**
- 三组：全模板、全动态、混合（现状）
- 指标：构图时延 p50/p95、规划期 token、图节点数、无人工干预完成率
- 图：分组柱 + 散点抖动，n≥30，误差棒写 p95
- 关键：**必须承认动态组在长尾任务上更好**，混合的价值是"两端都不差"，不是"全面更好"。这种诚实反而加分。

**实验 A3｜LLM 解析 vs 启发式降级一致性（附录）**
- 40 条金标画像，对比 LLM 解析与超时降级的字段一致率
- 图：混淆矩阵热力图（复杂度 / 风险等级两栏）
- 用途：证明"模型挂了规划不挂"不是口号。

### B. 执行器（就绪集并行 + 超步 + 编译）

**实验 B1｜变宽度合成 DAG 加速比（必做，正文主图）**
- 构造：深度 L 固定（如 8 层），宽度 w ∈ {1,2,4,8,16}；每步固定 200ms sleep（排除模型抖动）
- 测：墙钟时间、超步数、最大并发
- 图：**甘特图**（x=时间，y=节点，色=状态，框上标 readySet 批次）+ 右侧加速比折线（实测 vs 理论上界 min(P, W/L)）
- 结论句式：「w=8 时 3.7× 加速，达理论上界的 92%；w=16 受 P 截断后不再增长。」
- 展示：这是答辩第一张图。它把"动态拓扑"从名词变成一个能看的时间轴。

**实验 B2｜调度开销随规模（附录，验证复杂度）**
- N ∈ {10, 50, 100, 500, 1000}，纯 CPU，无 IO
- 图：双对数坐标，实测点 + O(N·d̄) 参考线
- 用途：回应"你这调度器是不是 O(N²)"这类问题。

**实验 B3｜max_parallelism 拐点（附录）**
- P 扫描 1→32，测吞吐；拐点通常在模型侧限流
- 图：吞吐-并发曲线，标拐点与限流原因
- 叙事价值：证明并发上限是"测出来的"，不是配置里随便写的。

### C. 通信器（Communication Broker：字段白名单 + 熵预算 + Provenance）

**实验 C1｜长程累积 token（必做，正文主图）**
- 同一任务链跑到 50 步，两种策略：全量上游拼接 vs 按 input_spec 投递
- 图：累积 token 曲线，两条线 + 中间阴影，阴影面积标注"累计节省 X%"
- 起点可复用现有实测：菱形图 3157→11 token（99.65%），但**必须补成曲线**，单点数字在答辩里会被打穿

**实验 C2｜节省率随字段数/上游规模（附录热力图）**
- 网格：F ∈ {1,2,4,8} × 上游规模 S ∈ {0.5k, 2k, 8k, 32k}
- 图：节省率热力图，等值线标 90%
- 用途：说明"什么时候低熵才有意义"——S 小、F 大时收益有限，主动交底比被问出来强。

**实验 C3｜质量守恒（必做，和 C1 成对出现）**
- 30~50 道有标准答案的任务，每题跑两遍（全量 / 低熵）
- 图：配对点图（x=全量得分，y=低熵得分，对角线）+ 一致率；必要时 Wilcoxon
- 结论句式：「配对样本 42/45 完全一致，3 例差异均出现在需要跨步复述原文的题上。」——把边界说清楚。
- 注意：**没有 C3，C1 的 99% 就是负分项**，评委第一反应必然是"你把上下文砍了当然省"。

### D. 恢复器（Checkpoint + 失败分类 + 配方 + GraphPatch）

**实验 D1｜故障注入矩阵（必做，正文）**
- 3 类故障（timeout / crash / empty_evidence）× 3 个注入位置（早期 / 中期 / 晚期）× 自愈开/关
- 图：2×3×3 完成率热力图（两个 panel：关自愈 / 开自愈）
- 结论句式：「开自愈后 9 种组合全部收敛至完成，recoveryCount 中位数 1。」
- 这张图回答赛题原话："接受动态注入异常、无人工干预自主完成闭环"。

**实验 D2｜重复工作量与故障位置无关（正文，最有洞察的一张）**
- 同样 30 步任务，在第 5 / 15 / 25 步注入故障，测重复执行步数与重复 token
- 对照：无检查点从头重跑
- 图：横轴=注入位置，纵轴=重复步数；两条线（有检查点≈常数 / 从头重跑=线性上升）
- 这是"两线交叉"型结论，比任何百分比柱状图都容易被记住。

**实验 D3｜恢复泳道时间线（正文配图 / 演示视频截图）**
- x=时间，三条泳道：执行 / 检查点 / 治理事件；标注 STEP_FAILED→CHECKPOINT→RUN_RECOVERED→STEP_SUCCEEDED
- 用途：D1/D2 的"证据截图"，也是产品内 Trace 视图的真实产出，不是画出来的。

**实验 D4｜恢复正确性（附录，一句话+表）**
- 恢复后产物 vs 无故障基线：字段级 diff + 哈希一致率
- 图：可省略图，用一张 12 行的表；图省下来给 D2。

### E. 资源调度（端-边-云、租约、重绑定）

- **E1 边缘断连回迁时序图**：edge 心跳丢失 → 健康刷新 → 云端重绑定 → 续跑；标各段耗时
- **E2 切换时延分布**：n=50 次断连，箱线图，标 p50/p95
- **E3 租约冲突率 vs 并发节点数**（附录）：证明租约不是空转
- 呈现：这组适合放**演示视频**（拔网线/杀进程），静态图放附录。视频里的一次真实回迁 > 三张图。

### F. 治理与审计（Auditor / Risk / Decision / Provenance）

- **F1 三链路闭合审计**：随机 50 个 run，检查 Trace / Provenance / Decision 是否都能从结论回溯到原始输入
- 图：桑基图（结论 → 步骤 → 数据 → 原始材料），或极简 100% 堆叠条 + 失败样本列表
- **F2 高风险节点识别**：构造 20 个"应当人审"的任务，测召回/精确率 → 混淆矩阵
- 呈现：合规是叙事强项，图要给"闭合率 50/50"这种硬数字，别给流程图（流程图已有架构图了）。

### G. 演化（Skill / Graph 版本）

- 版本迭代 vs 成功率 / 复用率阶梯图；含一次回滚案例
- 呈现：附录一页。这个部件目前证据薄，别在正文抢位置。

### H. 端到端

- **H1 长程稳定性**：200 步任务，横轴=步序，纵轴=单步时延 / 内存 / 累计 token（小倍数三连图）
- **H2 公开集小样本**：LongBench-E 6 样本冒烟（hotpotqa_e / gov_report_e / passage_retrieval_en_e 各 2）
  - 图：case 卡（题目 → 图快照 → 答案 → 得分），**不要做柱状图**，n=6 画柱状图是自曝其短
  - 表述必须写"冒烟/链路验证"，不能写"效果优于 X"
- **H3 同题对照**：同一合同审查任务，知弈 vs 单体 Agent（全量上下文）的 token / 时延 / 交付完整度
  - 图：斜率图（slope chart）比雷达图好；雷达图 5 维面积无意义，慎用

## 3. 图表规范（统一，避免 8 张图 8 种风格）

| 项 | 规定 |
| :--- | :--- |
| 标题 | 写结论，不写"图 4-3 加速比"；例：「宽度 8 时加速 3.7×，达理论上界 92%」 |
| 基线 | 每条主张线必须配一条灰色虚线基线，图例写全（全量拼接 / 从头重跑 / 串行） |
| 误差 | n<30 用散点全画出来；n≥30 用 p50 + p95 误差棒；禁止只报均值 |
| 单位 | token / ms / 步 三种，图上直接标，不要放正文解释 |
| 颜色 | 主色（主张）实线深色；基线灰虚线；第三组用同色系浅色。不用红绿区分（色弱 + 中式涨跌歧义） |
| 脚注 | `scripts/exp/xx.py --case b1 · data/exp/b1.json · n=30 · commit abc1234` |
| 单图信息量 | 一张图一个结论；要两条结论就拆两张，附录不缺位置 |

## 4. 怎么呈现：三层结构

**第一层 · 正文主张图（6 张，一页一图）**
B1 甘特+加速比 → C1 累积 token（配 C3 质量守恒小图） → D2 重复工作量 → A1 阈值曲线 → F1 闭合率 → H3 同题斜率图。
顺序即论证顺序：能并行 → 省 token 且不降质 → 坏了能自己好 → 规划不是玄学 → 全程可审计 → 整体比单体强。

**第二层 · 附录证据（12~15 张）**
热力图、混淆矩阵、复杂度双对数、时延分布、租约冲突、版本阶梯。附录的作用不是"显得多"，是**让评委抽查任意一张都能对上主图**。

**第三层 · 动态演示（3 段，各 20 秒）**
1. 菱形图并行：`/acg` 面板上两个分支同时亮
2. 故障注入：第 15 步 crash，Trace 出现 RUN_RECOVERED，进度条继续，recoveryCount=1
3. 边云回迁：杀掉边缘进程，任务在云端续跑完成
三段都用产品真实界面录屏，不做动画。答辩时先放视频，再翻到对应静态图，说服力最稳。

**答辩 90 秒话术模板（每个部件复用）**
> 我们的主张是「X」。反例是「Y」（给出对手数字）。这张图是 n=30 的对照，Z 指标从 a 到 b。边界是「W 条件下收益消失」。
—— 主张 / 反例 / 证据 / 边界，四句话，不要第五句。

## 5. 反模式（会被现场打穿的做法）

- 单次运行当结论（尤其 99.65% 这种单例，必须补 n 与曲线）
- 只报最好 case，不给分布
- 用 n=6 的公开集画柱状图并暗示"效果更好"
- 雷达图当总结（面积无意义，评委里有做评测的）
- 图里的数字和表里的数字对不上（自查一遍再交）
- 声称"加速 8×"但没写 P 和关键路径下界
- 消融只删一个模块就宣称"该模块贡献 X%"（必须做全组合或至少 leave-one-out）

## 6. 实施顺序（按投入产出）

| 优先级 | 内容 | 理由 |
| :--- | :--- | :--- |
| P0（本周） | B1、C1+C3、D2 | 三张图撑起"并行 / 低熵 / 自愈"三个核心卖点，且都可用合成任务 + 固定 sleep 快速出数，不依赖模型质量 |
