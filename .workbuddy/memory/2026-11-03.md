### 实现细节讨论结论（供后续写文档时取用）
- A 检索：默认确定性嵌入应正名为 `DeterministicFallbackEmbedding`，指标分报 BM25-only / Hybrid / Δ；RRF k 随适配器切换（deterministic 20~40，真嵌入 60~100）；候选上限 100 改为分类型配额，Profile 与直接 ID 引用不占配额；硬门控采用按 tenant 分区索引为主 + 过采样兜底，越权召回数硬断言 0；TokenCost 移出打分放进装配阶段贪心背包，Conflict 分门控/惩罚两类，Utility 需 Beta 先验 + 10~15% 探索配额。
- B 存储：SQLite(WAL) 权威记录 + FTS5 external content + 可重建向量索引 + 邻接表递归 CTE + 大对象内容寻址；索引是权威表的物化视图，`index_version` 校验 + `memory_index_rebuild()`；多机边界建议按 task_id 分片复用 Resource Lease。
- C 预算：L0 不可压缩 / L1 高优先 / L2 value-per-token 贪心 / L3 引用化；降级必须使 estimated_tokens 单调下降，带 `degradation_attempt` 阈值防死循环；先引用化后摘要；摘要做数字/实体/日期抽取比对硬校验。
- D 事务：幂等键 `(task_id, run_id, step_id, attempt, batch_seq)`；大对象两阶段 + pending TTL 孤儿 GC；晋升异步状态机，PENDING 默认不参与在线召回；Capsule 按事实性/非事实性字段分层。
- E 契约：MemoryRecord 统一信封 / 在线三件套（Request、CandidateSet 必须带 rejected[]、ContextPack）/ MemoryWriteBatch；schema_version 复用通信器 Adapter 机制；MemoryService 只暴露 recall / assemble / commit 三方法。
